# Wireshark: HSRP packet capture guide

These screenshots are illustrative mockups of the expected Wireshark packet-list/details view, not captures from a live router. Use the steps below to capture genuine packets for your GitHub portfolio.

## Where to capture

Capture on a mirrored switch port / SPAN session for the client VLAN, or use a simulator's packet-capture feature on the shared LAN segment. HSRP hellos are exchanged between the routers on that shared segment.

## Display filters

- HSRP UDP traffic: `udp.port == 1985`
- HSRP v1 multicast destination: `ip.dst == 224.0.0.2 && udp.port == 1985`
- HSRP v2 multicast destination: `ip.dst == 224.0.0.102 && udp.port == 1985`
- Filter by a router address if needed: `ip.addr == 192.168.10.2 && udp.port == 1985`

HSRPv2 uses multicast destination `224.0.0.102`; HSRPv1 commonly uses `224.0.0.2`. Both use UDP destination port 1985. HSRP packets are not the same as ICMP echo packets generated by IP SLA.

## Fields to inspect

In a real capture, expand Ethernet, IPv4, UDP, and HSRP:
- IPv4 destination: expected HSRPv2 multicast `224.0.0.102`
- UDP destination port: `1985`
- HSRP version: `2`
- HSRP group: `10`
- State: commonly Active (`16`) or Standby (`8`) in HSRP packet fields, depending on packet
- Hello/hold timers: defaults are commonly 3 seconds / 10 seconds unless changed
- Virtual IP: `192.168.10.1`
- Priority: R1 is configured 110, R2 100; the packet reflects the sender's advertised priority

Exact field labels can vary by Wireshark version and packet dissector.

## What to say in your portfolio

1. The two routers exchange HSRP hello packets on the shared LAN.
2. HSRP elects an Active router; clients use the virtual IP as their default gateway.
3. IP SLA runs separately as ICMP probes toward `203.0.113.1`.
4. When the tracked SLA fails, R1's HSRP priority decreases by 30, allowing R2 to become Active.
5. The HSRP authentication configuration is a control-plane safeguard, not encryption of the whole packet or user traffic.

## Capture your own evidence

1. Start capture on the shared VLAN.
2. Apply filter `udp.port == 1985`.
3. Save a baseline screenshot showing packets and expanded HSRP fields.
4. Trigger the controlled SLA failure and capture the role/priority transition if visible.
5. Save captures as `.pcapng` if allowed by your lab and add your own screenshots to this folder.
